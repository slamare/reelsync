# reelsync

Self-hosted совместный просмотр с любого сайта — без браузерных расширений,
без демонстрации экрана и без загрузки видео на сервер. Комната, очередь,
синхронизация play/pause/seek между участниками.

## Как это работает

- Комнаты создаются автоматически при заходе на `/`, ссылка вида `/r/<id>`
- Любой участник добавляет ссылку в очередь через WebSocket
- Целевая страница проксируется через [Ultraviolet](https://github.com/titaniumnetwork-dev/Ultraviolet)
  поверх [bare-server-node](https://github.com/tomphttp/bare-server-node) —
  контент отдаётся с твоего домена, поэтому cross-origin ограничения браузера
  не мешают управлять чужим плеером
- Инжектится скрипт, который находит `<video>` на странице (включая вложенные
  iframe) и транслирует play/pause/seek в комнату и обратно

## Стек

- Node.js, Express, `ws`
- Ultraviolet + bare-server-node — прокси произвольных сайтов
- Vanilla JS на фронте, без сборки

## Установка

### Proxmox (LXC одной командой)

```
bash -c "$(curl -fsSL https://raw.githubusercontent.com/slamare/reelsync/main/proxmox/create-ct.sh)"
```

Создаёт Debian 12 LXC, ставит Node.js, клонирует репозиторий, поднимает
`systemd`-сервис на порту `8080`.

### Вручную

```
git clone https://github.com/slamare/reelsync.git
cd reelsync
npm install
npm start
```

## Реверс-прокси

Нужен обратный проброс на порт `8080` с обязательно включённым
**WebSocket support** — без него не заработает ни синхронизация комнаты,
ни сам Ultraviolet-прокси (bare-server держит upgrade-соединения).

## Известные ограничения

- DRM-защищённые плееры (Widevine и т.п.) идут через тот же общий прокси,
  что и обычные сайты — если сработает анти-бот или защита плеера,
  воспроизведение не запустится. Отдельного обхода под конкретные сервисы нет
- Определение `<video>` на странице автоматическое; если на странице
  несколько video-элементов (реклама, превью), возможен ложный выбор
- Чат и аккаунты сознательно не реализованы — только синхронизация плеера
